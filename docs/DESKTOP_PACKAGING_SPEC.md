# Desktop Packaging Specification — Tauri 2 (Production Grade)

**Version:** 1.0.0
**Status:** Authoritative for the desktop shell and release pipeline
**Owner:** OpenCode (shell, installer, CI) · Gemini Antigravity (sidecar packaging inside `backend/`)
**Parent plan:** `docs/FINAL_EXECUTION_PLAN.md`
**Baseline:** `ARCHITECTURE_PLAN.md` v2.2

---

## 1. Goal

Ship **JobSeeker** as a signed, self-updating Windows desktop application:

- One installer, no terminal, no browser tab, no Python/Node installed by the user.
- Double-click → native window → dashboard. The automation Chrome remains a separate, visible window.
- Everything local: SQLite, artifacts, keys, browser profile.
- Production-grade: crash recovery, signed updates, migration safety, least-privilege capabilities, diagnostics, uninstall that respects the user's data.

**Non-goal:** remote/multi-user hosting, mobile, macOS/Linux in v1 (the architecture allows them later).

---

## 2. Runtime topology

```
┌──────────────────────────────────────────────────────────────┐
│ JobSeeker.exe  (Tauri 2 shell, Rust)                            │
│  • window (WebView2)  • tray  • updater  • notifications     │
│  • supervisor for the sidecar  • single-instance guard        │
└───────────────┬──────────────────────────────┬───────────────┘
                │ loads static UI               │ spawns + supervises
                ▼                               ▼
      frontend/out (Next.js export)     autojob-core.exe (Python sidecar)
      http://tauri.localhost            127.0.0.1:<random port>
                │                               │
                └──────── REST + WS ────────────┤
                 (Bearer token, per launch)     │
                                                ├── SQLite (WAL)
                                                ├── artifacts / screenshots
                                                └── Playwright → visible Chrome
```

Three processes on one machine: shell, Python backend, Chrome. The UI and the API are separate origins (Tauri custom protocol vs. localhost), so **CORS and a bearer token are required**.

## 3. Process lifecycle

### 3.1 Boot

1. Single-instance guard: if an instance exists, focus it and exit.
2. Create the app data directory and a per-launch 256-bit token (Rust `rand`, base64url).
3. Show a splash window ("Starting JobSeeker…") while the sidecar boots.
4. Spawn the sidecar **hidden** with `--data-dir`, `--host 127.0.0.1`, `--port 0`, `--parent-pid`, `--shutdown-grace 5`.
5. Read the sidecar's stdout handshake, line-delimited JSON:
   `AUTOJOB_READY {"port":52341,"token":"…","pid":7420,"version":"1.0.0"}`
   The sidecar generates the token itself; it never appears in argv.
6. On ready: create the main window, inject the bootstrap via a Tauri command (`get_bootstrap`), close the splash.
7. Timeout: 20 s → show a "Backend failed to start" screen with the log path and a Retry button.

### 3.2 Supervision

- If the sidecar exits unexpectedly, restart it (max 3 times in 10 minutes), then surface a crash dialog with logs.
- The UI shows a "Backend disconnected — reconnecting" banner and refetches on reconnect.
- The sidecar also watches `--parent-pid` every 2 s and exits if the shell died (prevents orphaned backends).

### 3.3 Shutdown

1. Window close / tray Quit → if an application run is active, confirm first.
2. `POST /internal/shutdown` (token, localhost only) with a 5 s grace period.
3. If the sidecar does not exit, kill the process tree.
4. Close the Tauri window; the updater may relaunch.

### 3.4 Crash recovery

- Sidecar crash mid-run: application rows left in `STARTING` / `AUTOFILLING` / `PAUSED_FOR_REVIEW` are reconciled on next boot to `FAILED` with `failure_stage = INTERRUPTED`, plus an audit record.
- A stale Chrome profile lock is detected and cleared only when the owning process is gone; otherwise the user is asked to close the automation window.
- All state that matters is in SQLite; the shell holds no business state.

## 4. Sidecar contract (local IPC)

This is **not** part of the public HTTP contract; it is the shell↔backend boundary.

| Item | Value |
| :--- | :--- |
| Binary | `autojob-core-<target-triple>.exe` (PyInstaller one-folder, **console subsystem**) |
| Spawn | hidden (`CREATE_NO_WINDOW`) via `tauri-plugin-shell` sidecar API |
| Args | `--data-dir <path> --host 127.0.0.1 --port 0 --parent-pid <pid> --shutdown-grace 5 --log-level info` |
| Handshake | one line on stdout: `AUTOJOB_READY {json}` (flush immediately) |
| Token | 32 random bytes, base64url; generated by the sidecar; constant-time comparison |
| Port | OS-assigned (`port=0`); reported in the handshake |
| Auth | `Authorization: Bearer <token>` on every `/api/v1/*`, `/ws/*`, and `/internal/*` request |
| WS auth | `ws://127.0.0.1:<port>/ws/telemetry?token=<token>` (query param; never logged) |
| Shutdown | `POST /internal/shutdown` (token) → graceful, then process kill |
| Logs | stdout/stderr forwarded by the shell to `%APPDATA%\JobSeeker\logs\backend.log` |
| Exit codes | `0` clean · `78` config/migration failure · `1` unexpected crash |
| Build | PyInstaller **console** build (windowed mode breaks stdout handshake), one-folder |

**Why a token:** any local process (or a malicious website via DNS rebinding) can reach `127.0.0.1`. The token plus a strict `Host`/`Origin` check makes the API effectively shell-only. The token lives in memory only — never in localStorage, logs, the DB, or a file.

**Host validation:** reject requests whose `Host` is not `127.0.0.1:<port>` (or `localhost:<port>`). This closes the DNS-rebinding hole.

## 5. Frontend integration

### 5.1 Build target

- `next.config.ts`: `output: 'export'`, `trailingSlash: true`, `images.unoptimized: true`.
- Tauri `build.frontendDist = "../frontend/out"`.
- Dev keeps `next dev` on `:3000` against uvicorn on `:8000`.

### 5.2 Routing (static-export constraint)

Dynamic UUID segments cannot be statically exported. Detail routes become query-based:

| Screen | Route |
| :--- | :--- |
| Job detail | `/jobs?id=<uuid>` |
| Run monitor | `/runs?id=<uuid>` |

Everything else stays as documented. Pages using `useSearchParams()` are wrapped in `<Suspense>` (required by static export). Client-side navigation still works normally.

### 5.3 Bootstrap and API client

The shell exposes `get_bootstrap()` → `{ apiBase, wsBase, token, version, platform }`.
The client initializes from it on first render; until it resolves, the app shows a skeleton, not an error.

- Desktop: `apiBase = http://127.0.0.1:<port>/api/v1`, token attached as `Authorization`.
- Dev web: `NEXT_PUBLIC_API_BASE`, no token.
- Never persist the token.

### 5.4 Native integration surface

| Capability | Plugin / API | Used for |
| :--- | :--- | :--- |
| Notifications | `tauri-plugin-notification` | HITL review, CAPTCHA alert, update ready |
| Sound | bundled `chime.ogg` via `<audio>` | HITL/CAPTCHA chime (respects mute setting) |
| Save/download | `tauri-plugin-dialog` + `@tauri-apps/plugin-fs` | Save resume/cover letter PDF, export diagnostics |
| Open externally | `tauri-plugin-opener` | Job posting links, data folder, log folder (http/https allowlist only) |
| Window state | `tauri-plugin-window-state` | Remember size/position/maximized |
| Tray | Tauri `TrayIconBuilder` (Rust) | Open, Pause automation (optional), Quit |
| Updater | `tauri-plugin-updater` + `tauri-plugin-process` | Check, download, verify, relaunch |
| Logging | `tauri-plugin-log` | Frontend errors and Rust logs to rotating files |
| Autostart | `tauri-plugin-autostart` | Optional, off by default |
| Single instance | `tauri-plugin-single-instance` | Focus existing window |

**External-link rule:** only `http:`/`https:` URLs may be opened, and only after a user click. Job titles/URLs from scraped data are never auto-opened.

### 5.5 Desktop UX states

- **Splash/starting:** branded, with a progress hint and "This can take a few seconds on first launch."
- **Backend unavailable:** error screen with Retry, Open logs, Export diagnostics.
- **Offline:** banner; crawling and LLM calls pause, local screens still work.
- **Update available:** non-blocking banner → release notes → download progress → "Restart to update."
- **About:** app version, contract version, sidecar version, data folder, log folder.
- **First run:** checks WebView2 (installer handles), Chrome runtime availability, data folder, LLM key.
- **Tray:** idle/running/paused icon state; "Open JobSeeker", "Quit". Pause is optional (requires an additive contract endpoint).

### 5.6 Frontend security rules

- Render job descriptions as text/markdown — never raw HTML, never `dangerouslySetInnerHTML` on scraped content.
- No remote fonts, scripts, images, or iframes.
- No `eval`, no `new Function`.
- Never render the token or absolute machine paths in the DOM.
- All downloads go through the dialog/fs plugins, not `window.open`.

## 6. Tauri configuration & capabilities

### 6.1 Window

- Default 1280×820, min 1024×700, native decorations (custom titlebar is a later polish item, not a v1 risk).
- Hidden until the sidecar handshake succeeds (no white flash).
- `useHttpsScheme: false` on Windows so `http://127.0.0.1` and `ws://` are not blocked as mixed content. **Verify on the target WebView2 version.**

### 6.2 CSP (shape — verify against the installed Tauri version)

```
default-src 'self';
connect-src 'self' http://127.0.0.1:* ws://127.0.0.1:*;
img-src 'self' asset: http://127.0.0.1:* data: blob:;
style-src 'self' 'unsafe-inline';
script-src 'self' 'unsafe-inline';
font-src 'self';
object-src 'none'; frame-src 'none'; base-uri 'self'; form-action 'none';
```

`'unsafe-inline'` for scripts/styles is a documented trade-off: Next.js static export hydrates with inline scripts, and all content is bundled locally. The real boundary is: no remote content, no navigation, token-gated API. Revisit with build-time hashes if the export allows it.

### 6.3 Capabilities (least privilege)

Grant only: `core:default`, shell sidecar spawn/execute (scoped to `autojob-core`), dialog, fs (scoped to app data + user-chosen save paths), notification, opener (http/https), updater, process relaunch, window-state, single-instance, autostart, os, log. No arbitrary command execution, no broad filesystem scope, no remote URL permissions.

### 6.4 Bundle

- `identifier`: `com.autojob.desktop` (rename with the final product name).
- `productName`: display name.
- Targets: NSIS (`installMode: currentUser`), optional MSI later.
- Icon set generated from one source.
- `externalBin`: the sidecar.
- WebView2: `downloadBootstrapper` (online installer) or `embedBootstrapper` for offline builds.
- App data: `%APPDATA%\JobSeeker\` (Tauri `app_data_dir`).

## 7. Security model

| Threat | Control |
| :--- | :--- |
| Another local process calls the API | Per-launch bearer token; token only in shell memory |
| Malicious website reaches localhost (DNS rebinding / CSRF) | Strict `Host` check, CORS allowlist, token header, no cookies |
| Token leakage via logs | Redaction filter; never log `Authorization`, `?token=`, or IPC payloads |
| XSS from scraped job text | Text/markdown rendering only, CSP, no remote content |
| Malicious update | Tauri updater signature verification (minisign) |
| Arbitrary command execution | Capabilities scoped to the single sidecar; no generic shell |
| Path traversal on artifacts | Serve by known ID/path within the data dir; reject `..` and absolute escapes |
| PII exposure | Local only; per-user ACL on `%APPDATA%`; screenshots never uploaded |
| Secret leakage | OS keyring only; tokens/keys redacted; diagnostics exclude secrets and screenshots by default |
| Devtools in production | Disabled in release builds |

**Accepted risk:** SQLite is unencrypted at rest; the OS user ACL is the boundary. Documented, not hidden.

## 8. Data, migration, and backup

```
%APPDATA%\JobSeeker\
  data\autojob.db (+ -wal, -shm)
  data\browser-profile\
  data\output\            (resume/cover PDFs, screenshots)
  data\backups\           (VACUUM INTO, pre-migration)
  browsers\cft-<version>\ (Chrome-for-Testing, if used)
  logs\                   (desktop.log, backend.log, rotating 10MB × 5)
  run\                    (transient; no secrets)
```

- On every launch: verify schema version. If a migration is needed, write `backups/pre-migration-<timestamp>.db` first, then `alembic upgrade head`.
- Migration failure → exit `78`, show a repair screen with the backup path and logs. Never continue on a half-migrated DB.
- Weekly `VACUUM INTO` backup; keep the last 4; "Backup now" in Settings.
- Uninstaller asks: **Keep my data** (default) or **Delete everything**. Deleting requires typing the word `DELETE`.
- Export diagnostics: zip logs + health JSON + versions. Screenshots/PII excluded unless the user ticks "include artifacts".

## 9. Chrome runtime strategy

Priority order:

1. **Installed Google Chrome** (stable, supported version) via Playwright `channel="chrome"` — smallest installer, real browser.
2. **Bundled/downloaded Chrome-for-Testing**, pinned version, checksum-verified, stored under `browsers\cft-<version>\`.
3. If neither exists: onboarding blocks with a clear "Install Chrome" action.

Rules:

- Never use the user's daily Chrome profile. The automation profile lives under `data\browser-profile\`.
- Pin the CFT version in config; verify SHA-256 before extraction; resume/retry on network failure.
- Detect the browser at launch and record the chosen executable in the health payload.
- On startup, detect stale profile locks. If the lock owner is gone, clean it; if not, ask the user to close the automation window.
- Playwright driver (`node` binary) is bundled by PyInstaller; browsers are **not** bundled in the default installer (first-run download).

## 10. Installer and code signing

- **NSIS per-user installer** (`currentUser`), no admin prompt, Start Menu shortcut, optional desktop shortcut, uninstaller.
- App id stable across versions; upgrades install over the previous version and keep `%APPDATA%`.
- **Authenticode signing** for the installer, app exe, sidecar exe, and DLLs; SHA-256 with RFC 3161 timestamping.
- SmartScreen: unsigned builds show "Unknown publisher". Options, in order:
  1. Azure Trusted Signing (cheapest managed option) via Tauri `signCommand`.
  2. Standard OV certificate (~$200–400/yr).
  3. Unsigned internal channel only, clearly labeled in the About screen.
- SHA-256 checksums published with every release.

---

## 11. Updates

- `tauri-plugin-updater` with minisign keys.
- Manifest: `latest.json` per channel (`stable`, `beta`), hosted on **GitHub Releases** (free, HTTPS).
- Private signing key: CI secret + offline backup; public key in `tauri.conf.json`. Losing the key breaks updates — back it up.
- Flow: check 5 s after launch, then every 6 h → banner with release notes → download → signature verify → pre-update DB backup → install → relaunch.
- Downgrade is manual: reinstall the previous version **and** restore the matching backup. Documented in the About/Help screen.
- The updater never runs during an active application; it defers with a toast.

---

## 12. Observability and diagnostics

- Local logs only. **No telemetry, no analytics, no crash uploads.**
- Rust panics, sidecar stderr, and frontend errors all land in rotating files.
- "Export diagnostics" produces a zip the user can inspect before sharing.
- Health surface: sidecar version, DB schema version, browser executable, Chrome profile path, keyring availability, LLM configured/degraded, scheduler states.
- Performance counters logged: boot time, sidecar ready time, page load, PDF render.

## 13. CI/CD (GitHub Actions, free)

`windows-latest` workflow on tags and nightly:

1. Checkout; setup Node 22, Python 3.12 + `uv`, Rust stable.
2. Cache: uv, npm, cargo, PyInstaller.
3. `uv sync` → `pytest`.
4. `npm ci` → `npm run lint` → `npm run typecheck` → `npm run build`.
5. PyInstaller sidecar → rename with target triple → `desktop/src-tauri/binaries/`.
6. `tauri build` (NSIS).
7. Sign (if secrets present); generate updater artifacts + `latest.json`.
8. Upload to GitHub Release draft; publish checksums.
9. Security scans: `pip-audit`, `npm audit --omit=dev`, `cargo audit`; Dependabot enabled.

Artifacts: installer, portable zip (optional), `latest.json`, checksums, SBOM (optional), symbol files.

| Case | Expected |
| :--- | :--- |
| Windows 11 24H2, clean VM, no Python/Node | Installer works, app boots, onboarding completes |
| Windows 10 22H2 | Same |

| App killed mid-run | Next launch reconciles, no duplicate submit |
| Two launches | Second focuses the first window |

| Antivirus scan | Signed binaries; no quarantine |
| Low disk | Clear error, no corrupted DB |
| Long paths | Install and artifacts work |
| Update while run paused | Deferred until idle |
| Invalid update signature | Rejected, current version keeps running |

| Milestone | When | Scope | Acceptance |

## 17. Risks

| Risk | Mitigation |
| :--- | :--- |
| PyInstaller + Playwright driver packaging | Hardest task; do it in D0/D1, test on a clean VM, keep one-folder mode |
| WebView2/WS mixed-content edge cases | `useHttpsScheme: false`, verify early; fallback: Tauri WS plugin |
| SmartScreen reputation | Sign; publish checksums; expect a warm-up period |
| Updater key loss | Offline backup of the private key; documented recovery |
| Installer size | System Chrome first; CFT as first-run download |
| Antivirus false positives | Signed, one-folder, no packers; test with Defender |
| Migration failure on upgrade | Pre-migration backup + repair screen; never auto-downgrade |
| Two-process port/token bugs | Port 0, handshake timeout, supervisor, integration test in CI |

---

## 18. Out of scope (v1 desktop)

macOS/Linux builds, Microsoft Store, MSIX, portable mode, custom titlebar, multi-window, deep-link protocol, background auto-apply when the window is closed, and encrypted SQLite. All are additive later.
